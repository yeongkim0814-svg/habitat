# M0 그래픽 비교 스파이크 (Issue #20, #22)

같은 테스트 장면을 렌더링 스타일 4가지(PSX, TOON, FLAT, PAINT)로 비교한다. **에셋 파일 없이 코드로만 만들었고**(저장소 규칙 2), 반복 구조는 모두 MultiMesh다(D19). 목적은 최종 아트가 아니라 "어느 방향이 이 게임의 분위기와 태블릿 성능에 맞는가"를 판단할 근거를 만드는 것이다. 애니메풍 캐릭터는 만들지 않았고(D12), Fate Trigger는 식생·바위·지형의 분위기 참고로만 생각했다.

## 실행

저장소 루트에서 Godot 4.6.x 이상으로 `res://spikes/m0_look/main.tscn`을 연다.

```sh
godot --path . res://spikes/m0_look/main.tscn
# 스크린샷(가상 화면에서): look = psx|toon|flat|paint, view = street|field|meadow|overhead, --hour=0~24, --zone=safe|danger
godot --path . --rendering-driver opengl3 --resolution 1280x720 res://spikes/m0_look/main.tscn -- --shot=paint:meadow:/tmp/paint_meadow.png --hour=10 --zone=safe
# 헤드리스 구조 검사
godot --headless --path . -s tests/m0/run.gd
```

화면 아래 버튼: 윗줄은 스타일 4개(PSX / TOON / FLAT / PAINT)와 시점 4개(거리 / 들판 / 초원 / 머리 위), 아랫줄은 시각 -3시 / +3시, 구역(안전 ↔ 오염), 조절, 측정. 시작 룩은 FLAT(D49). **측정**은 스타일 4 × 시점 4를 90프레임씩 재서 화면과 로그에 `M0 look=… view=… mean_ms=… p95_ms=… render_cpu_mean_ms=… render_gpu_mean_ms=… vsync=…` 줄로 보여 준다. Compatibility 렌더러는 수직동기를 끌 수 없어 프레임 시간(mean_ms, p95_ms)이 주사율 간격에 묶이므로, **렌더러 CPU·GPU 시간(render_cpu_mean_ms, render_gpu_mean_ms)을 스타일 비교의 기준**으로 본다(S1 측정과 같은 방식, GPU 시간이 보고되지 않으면 `?`).

## 장면 구성

| 부분 | 내용 | 그리는 방식 |
|---|---|---|
| 거주구역 거리 | 양쪽 건물 약 20개, 가로등과 전구 | MultiMesh 3개 + 바닥 1개 |
| 오염구역 들판 | 바위 110개, 외계 줄기 420개, 잎 1,260개, 열매 420개, 완만한 지형 | MultiMesh 4개 + 지형 1개 |
| 머리 위 반대쪽 구역 | 건물 1,200개(원통 위쪽, 축 방향으로 매달림) | MultiMesh 1개 |
| 원통 | S2의 32개 구간 메시(길이를 늘려 끝이 보이지 않게 함, 비교용) | 구간 메시 32개 |

## 스타일

| 스타일 | 구현 | 인상 |
|---|---|---|
| PSX | 화면을 1/4 해상도로 그린 뒤 최근접 확대, 꼭짓점 격자 흔들림, 색 단계화, 4단 조명, 짙은 안개 | 거칠고 어두운 분위기, 무서움에 유리, 먼 곳이 뭉개져 잘 안 보임 |
| TOON | 3단 셀 조명 + 뒤집은 껍질 외곽선, 채도 높은 색 | 식생·바위가 가장 읽기 쉬움, 외곽선 두께는 거리에 따라 보정 필요 |
| FLAT | 화면 미분으로 면마다 법선을 계산한 평면 음영, 옅은 안개 | 차분하고 깨끗함, 저폴리 모양이 그대로 드러남 |


## 조절 패널 (D49)

"조절" 버튼으로 연다. 그래픽을 말로 설명하는 대신 직접 만져서 값을 찾는 도구다(개발용, 최종 게임에는 넣지 않는다).

- 역할 고르기: ◀ ▶로 도로, 건물 벽, 초원 바닥, 바위, 침엽수 등 14개 역할을 넘기고, 색상·채도·명도 슬라이더로 색을 바꾸면 장면에 바로 반영된다.
- 전체 값: 안개 밀도, 주변광 배수, 태양 세기 배수.
- **초기화**: 현재 룩의 조절을 모두 지운다. **저장**: 룩별로 `user://m0_tuning.json`에 저장되고 다음 실행과 스크린샷에도 적용된다. **값 표시**: 바꾼 값을 JSON으로 화면과 로그에 보여 준다. 이 화면을 스크린샷으로 보내면 값을 그대로 전달할 수 있다.
- 시점·구역·룩을 바꿔도 저장하지 않은 조절은 이번 실행 동안 룩별로 유지되고, 저장해야 다음 실행에 남는다. 저장 파일의 안개·주변광·태양 값은 슬라이더 범위로 잘라서 읽는다.
- 측정(벤치마크)에도 저장된 조절 값이 적용되므로, 룩끼리 비교할 때는 먼저 초기화한다.
- 룩의 팔레트 상수(`looks.gd`)는 그대로이고 조절 값이 그 위에 덮인다. 저장 파일이 깨져 있으면 조용히 무시한다.

## 룩 심화 시험 1: FLAT 건물 디테일 (Issue #28)

사용자 평가("FLAT이 단조롭다")에 따라 FLAT의 **벽 머티리얼**(`SHADER_FLAT_WALL`)에 디테일을 셰이더로 그렸다. 메시와 draw call은 늘지 않는다(D19).

- 창 격자(폭 3 m 간격, 층 높이 3.2 m, 창 1.5 × 1.7 m), 1층의 문, 층 구분선, 창 위 그림자, 지붕 윗면 톤 다운.
- 건물은 단위 박스를 건물마다 스케일한 인스턴스라서, `VERTEX × 스케일`이 곧 미터 단위 로컬 좌표다. UV 없이 건물마다 창 개수가 맞게 배치된다.
- 밤(태양 고도가 낮을 때)에는 창의 약 40%가 따뜻한 빛으로 켜진다(`Looks.set_night`, `world.gd`의 `apply_time`).
- 70 m부터 무늬가 사라지기 시작해 150 m에서 없어진다(먼 곳 지글거림 방지).
- 알려진 한계: 건물 모서리의 창 배치는 단순하고, 지붕 형태는 그대로 평평하다. 머리 위 반대편 건물(천장 역할)은 이 셰이더를 쓰지 않는다.
- 확인 방법: 같은 `--hour=10`과 `--hour=20`에서 `--shot=flat:street:…`로 전후를 찍는다. 태블릿에서는 "측정"으로 GPU 시간을 비교한다.

## 회전하는 태양 (D43)

`sun.gd`(순수 함수)가 시각에서 태양 방향·고도·빛 색·하늘색·환경광 색을 계산한다. 태양은 원통 축(Z) 둘레를 돌고, 빛은 축과 각도 α(기본 35°)로 들어온다. 바닥 한 지점은 태양이 반대편에 있을 때 가장 밝으므로 **안전구역이 정오일 때 오염구역은 한밤중**이다(반대 위상).

- 헤드리스 검사(`tests/m0/run.gd`): 안전구역 정오 고도 = α, 해돋이·해넘이 고도 0, 두 구역의 고도가 항상 반대 부호, 각 구역이 하루의 정확히 절반 동안 밝음.
- 화면: 방향광 하나(그림자 켬, 보이는 범위 160 m), 시각·구역 버튼. 구역 버튼은 오염구역 바닥(원통 위쪽, 장면이 뒤집힘)으로 시점을 옮긴다.
- 그림자는 원통 길이(Z) 방향으로 길게 눕는다. 해돋이는 붉고 낮은 각도, 정오는 하얗고 높은 각도, 밤은 환경광만 남는다.
- 단순화: 원통 끝에서의 가림은 무시하고 전체에 평행광을 쓴다. 하루 길이는 물리(실제 외부 태양은 약 63초에 한 바퀴)가 아니라 설정값이다.

## 네 번째 스타일 PAINT (Fate Trigger 참고)

사용자가 제공한 참고 이미지(밝은 하늘, 손그림 느낌의 침엽수·활엽수, 풀 다발, 푸른 그림자, 부드러운 안개)를 **코드만으로 근사**했다. 에셋 파일과 외부 코드는 쓰지 않았다.

| 요소 | 구현 |
|---|---|
| 잎·줄기 명도 | 메시 꼭짓점 색으로 아래는 어둡고 위는 밝은 그라데이션(`nature.gd`) |
| 나무 | 침엽수 = 원뿔 3단, 활엽수 = 겹친 덩어리 3개의 수관(법선을 구형으로 둥글게)과 줄기 |
| 풀 | 날 5장짜리 다발 2,200개, 끝이 노랗고 바람에 흔들림(셰이더) |
| 질감 | 월드 좌표의 값 노이즈 2단(큰 얼룩과 작은 붓질)으로 색을 흔듦 |
| 빛 | 감싸는 조명(wrap), 환경광을 푸르게 해 그림자에 푸른 기 |

이 초원 시점은 다른 세 스타일에서도 같은 장면으로 보인다(모두 MultiMesh: 바위, 침엽수, 수관, 줄기, 풀).

## 이번 단계의 한계

- PAINT는 아직 지면이 과하게 밝고(노출 조정 필요), 바위 모양이 단순하다. TOON·PSX는 새 조명에 맞춰 다시 조정하지 않았다(침엽수가 어둡게 보임).
- 풀은 날이 단순해 가까이서 보면 거칠다. 밀도와 구역 나누기는 태블릿 측정 후 정한다.
- 손으로 그린 텍스처의 밀도는 에셋 없이는 한계가 있다(P4에서 외부 에셋 또는 AI 생성 텍스처, D26·외부 에셋 규칙을 따름).

## 알려진 한계 (M0 첫 PR)

- 스크린샷은 **가상 화면의 소프트웨어 렌더링**이다. 색감과 구성은 볼 수 있지만 프레임 시간은 의미가 없다. 태블릿 프레임 시간은 사용자가 측정 버튼을 눌러 기록해야 한다(미실행).
- 식생의 잎은 단순한 프리즘이라 모양이 거칠다. 최종 아트가 아니라 스타일 비교용이다.
- 머리 위 구역은 원통 길이를 늘려 확인한다(S2의 200 m 원통은 끝이 보인다). 실제 게임의 원통 길이는 미정이다.
- 외곽선(TOON)은 월드 단위 두께라 멀리서는 가늘어 보인다.
