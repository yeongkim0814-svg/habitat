# M0 그래픽 비교 스파이크 (Issue #20)

같은 테스트 장면을 렌더링 스타일 3가지로 비교한다. **에셋 파일 없이 코드로만 만들었고**(저장소 규칙 2), 반복 구조는 모두 MultiMesh다(D19). 목적은 최종 아트가 아니라 "어느 방향이 이 게임의 분위기와 태블릿 성능에 맞는가"를 판단할 근거를 만드는 것이다. 애니메풍 캐릭터는 만들지 않았고(D12), Fate Trigger는 식생·바위·지형의 분위기 참고로만 생각했다.

## 실행

저장소 루트에서 Godot 4.6.x 이상으로 `res://spikes/m0_look/main.tscn`을 연다.

```sh
godot --path . res://spikes/m0_look/main.tscn
# 스크린샷(가상 화면에서): look = psx|toon|flat, view = street|field|overhead
godot --path . --rendering-driver opengl3 --resolution 1280x720 res://spikes/m0_look/main.tscn -- --shot=toon:field:/tmp/toon_field.png
# 헤드리스 구조 검사
godot --headless --path . -s tests/m0/run.gd
```

화면 아래 버튼: 스타일 3개(PSX / TOON / FLAT), 시점 3개(거리 / 들판 / 머리 위), 측정. **측정**은 스타일 3 × 시점 3의 프레임 시간을 90프레임씩 재서 화면과 로그에 `M0 look=… view=… mean_ms=… p95_ms=…` 줄로 보여 준다(수직동기를 잠시 끄고 잰 뒤 되돌림).

## 장면 구성

| 부분 | 내용 | 그리는 방식 |
|---|---|---|
| 거주구역 거리 | 양쪽 건물 약 20개, 가로등과 전구 | MultiMesh 3개 + 바닥 1개 |
| 오염구역 들판 | 바위 110개, 외계 줄기 420개, 잎 1,260개, 열매 420개, 완만한 지형 | MultiMesh 4개 + 지형 1개 |
| 머리 위 반대쪽 구역 | 건물 1,200개(원통 위쪽, 축 방향으로 매달림) | MultiMesh 1개 |
| 원통 | S2의 32개 구간 메시(길이를 늘려 끝이 보이지 않게 함, 비교용) | 구간 메시 32개 |

## 스타일

| 스타일 | 구현 | 인상 |
|---|---|---|
| PSX | 화면을 1/4 해상도로 그린 뒤 최근접 확대, 꼭짓점 격자 흔들림, 색 단계화, 4단 조명, 짙은 안개 | 거칠고 어두운 분위기, 무서움에 유리, 먼 곳이 뭉개져 잘 안 보임 |
| TOON | 3단 셀 조명 + 뒤집은 껍질 외곽선, 채도 높은 색 | 식생·바위가 가장 읽기 쉬움, 외곽선 두께는 거리에 따라 보정 필요 |
| FLAT | 화면 미분으로 면마다 법선을 계산한 평면 음영, 옅은 안개 | 차분하고 깨끗함, 저폴리 모양이 그대로 드러남 |

## 알려진 한계 (이번 PR)

- 스크린샷은 **가상 화면의 소프트웨어 렌더링**이다. 색감과 구성은 볼 수 있지만 프레임 시간은 의미가 없다. 태블릿 프레임 시간은 사용자가 측정 버튼을 눌러 기록해야 한다(미실행).
- 식생의 잎은 단순한 프리즘이라 모양이 거칠다. 최종 아트가 아니라 스타일 비교용이다.
- 머리 위 구역은 원통 길이를 늘려 확인한다(S2의 200 m 원통은 끝이 보인다). 실제 게임의 원통 길이는 미정이다.
- 외곽선(TOON)은 월드 단위 두께라 멀리서는 가늘어 보인다.
